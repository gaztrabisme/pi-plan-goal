# U2 — Claude Code plan→goal plugin

Write only under claude-code/ (never touch claude-code/probe-sandbox/, never ~/.claude, never the project-root .claude/). Read anything in the repo. Do not git commit. POSIX sh plus python3 stdlib for hook scripts; they must work with /bin/sh on macOS. Write your final report even if the verdict is FAIL.

## Target
Claude Code 2.1.x. After the user approves a plan (ExitPlanMode), the agent must write a goal block to a file before editing; when it tries to stop, the block is validated and printed as a `/goal` line for the user to paste (the model cannot run /goal; hooks cannot run slash commands). Measured facts are in claude-code/probe.md — read it first; do not rely on docs where it disagrees:
- Approve: PostToolUse fires for ExitPlanMode; tool_input is {}; plan text in tool_response.plan; plan file path in tool_response.filePath (~/.claude/plans/*.md).
- Reject: PostToolUse never fires (only PreToolUse, PermissionRequest, Notification, Stop).
- Stop: blocking works with exit 2 + stderr, and with exit 0 + stdout {"decision":"block","reason":...}; both deliver the text to the model. Stop stdin carries stop_hook_active (false first, true on the resumed turn).
Goal-block format: spec/goal-block.md; validator bin/goal-block-check (exit 0 valid, 1 invalid with problems on stderr); fixtures spec/example.md, spec/fixtures/too-long.md (4001 chars), no-check.md, gap.md.

## Change
1. claude-code/bin/goal-block-check — byte-identical copy of bin/goal-block-check.
2. claude-code/hooks/post-exit-plan.sh (PostToolUse, matcher ExitPlanMode): read stdin JSON; state dir = <cwd>/.claude/plan-goal/; write `approved` containing the plan filePath and a plan title (first markdown heading or first line of tool_response.plan, trimmed to 80 chars); reset counters; print JSON {"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext": "<text>"}} where text (≤700 chars) tells the model: plan approved; before any edit write the goal block to .claude/plan-goal/goal.md; first line exactly `Execute plan "<title>" (<filePath>). Goal rows:`; then numbered rows `<n> <label>: <check>` each a concrete command or observable check; ≤4000 chars; validate with the checker path; then work the rows.
3. claude-code/hooks/pre-edit-gate.sh (PreToolUse, matcher Edit|Write|MultiEdit|NotebookEdit): if `approved` exists and goal.md is missing or invalid, deny the call with permissionDecision "deny" and a reason naming .claude/plan-goal/goal.md — except when the target file_path is the goal file itself (allow). Otherwise exit 0 silently. Check the current PreToolUse output schema in the official docs (https://code.claude.com/docs/en/hooks) if you have network; else use hookSpecificOutput.permissionDecision/permissionDecisionReason.
4. claude-code/hooks/stop.sh (Stop): no `approved` → exit 0 silent. Default mode: goal missing/invalid → block with exit 2 and stderr = checker problems + instruction, at most PLAN_GOAL_MAX_BLOCKS (default 3) times per plan (counter file); when the cap is reached or stop_hook_active is true AND the cap is reached, exit 0 with a systemMessage that the goal is still missing. Goal valid → remove `approved`, save goal as goal.active.md, print {"systemMessage":"Paste to set the goal:\n/goal <block>"} and exit 0 (the block is the validated text, header + rows). Loop mode (env PLAN_GOAL_LOOP=1): once the goal is valid, do not print the paste line; instead block with {"decision":"block","reason":"Goal active: keep working the rows in .claude/plan-goal/goal.active.md; when every row's check passes, write .claude/plan-goal/done with one line per row: <n> PASS <evidence>."} until `done` exists or 8 continuations have happened (counter), then exit 0 with a systemMessage stating which. Loop mode ignores stop_hook_active (it is always true while looping) and relies on the cap.
